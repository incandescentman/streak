* 2025-10-22: Added Bash Launcher Function

** Overview
Added a convenient bash function called =streak= to launch the tracker with a single command. This streamlines the workflow by automating server startup and browser launch.

** Implementation Details

*** Location
- =/Users/jay/Library/CloudStorage/Dropbox/apps/bash-profile/jay-scripts.sh:1328-1348=

*** Function Design
#+BEGIN_SRC bash
streak() {
  local streak_dir="/Users/jay/Library/CloudStorage/Dropbox/github/streak"
  local port=8001

  printf "Very good, sir. Launching your writing streak tracker...\n"

  # Navigate to streak directory and start server in background
  (cd "$streak_dir" && python3 -m http.server "$port" > /dev/null 2>&1 &)

  # Give the server a moment to start
  sleep 0.5

  # Open in browser
  open "http://localhost:$port"

  printf "📅  Tracker opened at http://localhost:$port\n"
  printf "To stop the server: pkill -f 'python3 -m http.server $port'\n"
}
#+END_SRC

*** Key Features
1. *Automatic directory navigation*: Uses absolute path to streak directory
2. *Silent background server*: Redirects output to /dev/null for clean UX
3. *Port selection*: Uses port 8001 to avoid conflicts with port 8000
4. *Browser auto-launch*: Opens default browser to tracker page
5. *User feedback*: Provides clear startup message and shutdown instructions
6. *Jeeves voice*: Matches existing script style with "Very good, sir" greeting

*** Benefits
- One-command launch: Just type =streak= from anywhere
- No need to remember directory paths or port numbers
- No need to manually open browser
- Background process allows continued terminal usage
- Clear instructions for stopping the server when done

* 2025-10-13: Critical Bug Fixes and Architecture Improvements

** Problems Identified

*** 1. Critical: CSS/JavaScript Grid Mismatch
**** Location
- =styles.css:17= - Grid configuration
- =script.js:78-83= - Month column addition

**** Problem Description
The CSS grid was configured for 7 columns, but the JavaScript was adding 8 elements per row (7 day cells + 1 month label). This caused the month column to wrap to a new row or display incorrectly.

#+BEGIN_SRC css
/* Original - WRONG */
grid-template-columns: repeat(7, 1fr);
#+END_SRC

#+BEGIN_SRC javascript
// JavaScript adds 8th element
monthElement.classList.add('month');
weekRow.appendChild(monthElement); // This breaks the layout!
#+END_SRC

**** Impact
- Month labels displayed incorrectly or wrapped to new rows
- Calendar grid layout was visually broken
- Inconsistent row structure across the page

*** 2. Missing CSS Styling for Month Column
**** Location
- =styles.css= - No =.month= class styling existed

**** Problem Description
The JavaScript created month column elements with the =.month= class, but no CSS styling was defined for this class. This meant month labels appeared unstyled with default browser styling.

**** Impact
- Month labels had no visual consistency with day cells
- No proper sizing, positioning, or styling
- Poor user experience with inconsistent visual design

*** 3. Fragile MISSED Status Detection
**** Location
- =script.js:41-42= - Status detection logic
- =progress.html:40= - HTML structure

**** Problem Description
The code detected MISSED entries by checking text content rather than using CSS classes:

#+BEGIN_SRC javascript
// Original - FRAGILE
statusSpan.classList.contains('todo') && statusSpan.textContent === 'MISSED'
#+END_SRC

This approach is fragile because:
- Depends on exact text matching (case-sensitive, whitespace-sensitive)
- Breaks if org-mode export changes text formatting
- Violates separation of concerns (mixing content with logic)

**** Impact
- Potential bugs if export format changes
- Harder to maintain and debug
- Non-idiomatic approach to DOM querying

*** 4. Unreliable Date Parsing
**** Location
- =script.js:73= - Date retrieval for incomplete rows

**** Problem Description
Code parsed formatted date strings from display text rather than storing/retrieving ISO dates:

#+BEGIN_SRC javascript
// Original - FRAGILE
const lastDate = new Date(weekRow.lastChild.querySelector('.full-date').textContent);
// Parsing "Sat, Jun 1, 2024" - locale-dependent!
#+END_SRC

**** Impact
- Locale-dependent parsing could fail in different environments
- Fragile dependency on display formatting
- Risk of date parsing errors with timezone issues

*** 5. Missing Error Handling
**** Location
- =script.js:14-30= - Main processing function

**** Problem Description
No error handling for:
- Empty or missing data in progress.html
- Malformed HTML structure
- Incomplete rows without proper day elements

**** Impact
- Silent failures with no user feedback
- JavaScript errors could crash the entire page
- Debugging difficulties in production

*** 6. Data Integrity Issues
**** Location
- =progress.html= - Timeline gaps

**** Problem Description
Timeline jumps from =2024-06-08= to =2024-06-30= (missing ~3 weeks of data).

**** Impact
- Irregular row lengths
- Visual inconsistencies in calendar
- Unclear whether this is intentional or data corruption

*** 3. Improved Status Detection with CSS Classes
**** Changes
- Updated =script.js:42= to use =classList.contains('MISSED')=

#+BEGIN_SRC javascript
// Before - FRAGILE
const status = statusSpan.classList.contains('done') ? 'DONE' :
               statusSpan.classList.contains('todo') && statusSpan.textContent === 'MISSED' ? 'MISSED' : 'TODO';

               statusSpan.classList.contains('MISSED') ? 'MISSED' : 'TODO';

**** Benefits
- Idiomatic DOM querying using CSS classes
- Immune to text formatting changes
- Cleaner, more maintainable code
- Better separation of concerns

*** 4. Enhanced Date Handling with Data Attributes
**** Changes
- Added =data-date= attribute storage in =script.js:37=

const lastDate = lastDateString ? new Date(lastDateString) : new Date();

**** Benefits
- Locale-independent date handling
- Direct access to ISO date strings
- No parsing of formatted display text
- Future-proof and reliable

** Lessons Learned

*** What Worked Well
- CSS Grid's =display: contents= for flexible row structure
- Data attributes for storing metadata alongside elements
- Vertical text orientation for space-efficient month labels

*** What to Watch For
- Grid column count must match actual elements added per row
- Always provide CSS styling for JavaScript-generated classes
- Prefer CSS classes over text content for logic decisions
- Store data in attributes, not in formatted display text

*** Testing Insights
- Local server required for =fetch()= API (not file:// protocol)
- Browser dev tools critical for debugging grid layout issues
- Git diff review essential for catching logic changes
